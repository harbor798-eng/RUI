# Detailed Analysis Delivery Contract

## 目的

将 Skill 对当前任务形成的判断、分析和必要说明，
以用户能够连续理解和阅读的完整结果交付。

Detailed Analysis 是分析型交付路径。
与 Quick Reply 不同，
这里允许保留完成当前分析任务所需要的分析过程和解释。

## 核心原则

### 1. 允许完整呈现必要分析

Skill 可以充分展开：
- 判断；
- 判断依据；
- 解释；
- 推断；
- 例子；
- 风险；
- 建议；
- 其他完成当前分析任务所需要的信息。

具体使用哪些内容，由 Skill 决定。

### 2. 不强制固定分析结构

不要要求固定的：
- 事实；
- 推断；
- 情绪；
- 关系；
- 建议；
- 核心判断；

等模块。

不要要求固定标题、固定顺序或固定分析栏目。

### 3. 保持 Skill 的完整表达

Detailed Analysis 应保持当前 Skill 的：
- 人格；
- 判断方式；
- 专业方法；
- 表达习惯；
- 语言风格；
- 分析视角。

不要因为进入 Detailed Analysis，
将 Skill 转换成统一的报告模板。

### 4. 分析服务于当前任务

虽然允许完整分析，
但仍应围绕当前 Function 所要求的问题。

不要为了展示分析能力而加入与当前任务无关的内容。

### 5. 不重新定义 Skill 的判断

Delivery 不负责改变：
- Skill 的结论；
- Skill 的判断方式；
- Skill 的人格；
- Skill 的分析方法。

Delivery 只负责将已经形成的分析结果交付给用户。

### 6. 使用连续、可阅读的最终文本

Detailed Analysis 默认以完整连续的文本交付。
不要自动拆分为多个预设分析模块、
折叠框或固定字段。

具体段落和表达方式由 Skill 决定。
